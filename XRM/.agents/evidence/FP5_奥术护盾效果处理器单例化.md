# FP-5 证据：奥术护盾效果处理器单例化 + 删旧补丁 + 参数错位核对

## 根因复核（行级）
- `Guice模块.java` 原未 `bind(奥术护盾效果处理器)`，故 Guice 每次注入新建实例 → 系统内并存 3 个实例（效果调度服务实现.getInstance / 伤害计算服务实现.@Inject / 战斗监听器.@Inject）。
- `内存效果服务` 原样保存 `效果实例`（含 `护盾吸收量` 参数覆盖），因此真实失败模式是「非共享精确护盾值表」而非「覆盖缺失」；单例化使 `on添加` 写入的精确值对 `吸收伤害` 全局可见。

## 修复
1. `Guice模块.java` 增加 `bind(mljy.技能实现.奥能法师.奥术护盾效果处理器.class).in(Singleton.class)`。
2. 删除 `奥术护盾效果处理器.java`：`待定精确值暂存` 静态字段、`暂存初始精确值` 方法、`on添加` 暂存分支（恢复从效果覆盖写入精确值表）；删除 `奥术护盾.java:97` 对其的调用。无残留引用（已 grep 确认）。

## 参数错位核对（关键发现：无需修改）
- `关键词解析器.替换参数`（关键词解析器.java:44-57）将 `{索引}` 映射为 `参数[索引]`（位置式）。
- `zh.yml` 定义：`护盾释放: "释放了[第{0}技能]，获得了可以吸收[伤害数值:{1}]点伤害的<yellow>奥术护盾</yellow>。"`，注释明确 `{0}=槽位中文数字, {1}=护盾值`。
- `奥术护盾.java:116`：`发送技能日志(施法者, "技能日志.护盾释放", 槽位中文数字, String.format(数值格式, 护盾值))` → 参数[0]=槽位、参数[1]=护盾值，与定义完全一致。
- 结论：当前代码与权威翻译定义已正确对应；若盲目交换参数反而会引入真实缺陷，故按 P0「无幻觉」不改动。
